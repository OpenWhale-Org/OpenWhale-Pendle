# OpenWhale Pendle Strategy（中文说明）

一个开源的 [Pendle](https://www.pendle.finance) 策略集合 —— 覆盖 Pendle V2（PT/YT 市场）和 Boros（利率互换），基于 [OpenWhale](https://github.com/OpenWhale-Org/OpenWhale) 框架。每个策略都是一个插件组件：把包装进运行中的网关，在看板上创建实例，调度、账户、执行和可观测性由框架负责。

npm 包名 `@openwhaleorg/pendle-strategy`。依赖场地插件 [`@openwhaleorg/pendle`](../openwhale-pendle)（凭证、账户、交易会话）和 `@openwhaleorg/core`。

## 策略列表

| 策略 | 产品 | 状态 | 一句话 |
|---|---|---|---|
| [Boros 挂单奖励](#1-boros-挂单奖励) | Boros | **已上线** | 在市场激励带最远边缘挂 post-only 单并跟随激励带移动，按带内流动性份额领取每小时预算 |
| Boros 资金费基差 | Boros | 规划中 | Boros 固定利率 vs 永续场地浮动资费的 carry |
| Pendle PT/YT 收益轮动 | Pendle V2 | 规划中 | 按隐含收益 vs 实际收益在 PT 与 YT 间轮动 |
| Pendle LP 激励挖矿 | Pendle V2 | 规划中 | 激励高于无常收益风险时做 LP |

"规划中"表示方向，不是承诺；欢迎开 issue 讨论。

## 安装

1. 在看板 **Plugins** 页先装 `@openwhaleorg/pendle`，再装 `@openwhaleorg/pendle-strategy`（填 npm 包名，或本地 checkout 的绝对路径）。
2. 按各策略的"准备"一节创建凭证和账户。
3. **Strategies → New strategy**，选策略、填参数、激活。

## 开发

```sh
pnpm install     # 在 workspace 根目录执行 —— 从同级的 OpenWhale checkout 链接 @openwhaleorg/core
pnpm build
pnpm test
```

## 1. Boros 挂单奖励

`pendle-strategy/boros-maker` · 监控 `pendle-strategy/market-watch` · 执行器 `pendle-strategy/maker`

一个实例只做一个 Boros 市场：在每一侧激励带的最远边缘挂一张 post-only 单，随中间隐含 APR 的移动跟着带走，按自己在带内流动性中的份额领取该侧的每小时预算。

### 工作原理

- **激励带。** 每个市场的每一侧（long / short）可能有一个 maker 激励活动：每小时的预算发给挂在中间 APR `±range` 范围内的订单。距离不加权 —— 带内每一 YU 拿到的一样多。
- **走廊。** 策略挂在离 mid `edgeRatio × range` 的位置（最远边缘：成交风险最低，奖励一样）。只要订单到 mid 的距离还在 `[safeDistanceRatio × range, range]` 内就不动它；只有订单漂出带外、或 mid 逼近到安全线以内时才重挂。
- **每 tick 一笔交易。** 一个 tick 里所有的撤单和挂单打包成一笔 Arbitrum 中继交易（`requote`），从账户的 USD gas 余额扣费，一次重挂约 $0.01–0.02。
- **规模。** 固定 YU，或**按保证金当前能开的量取百分比** —— 每个 tick 重算，尺寸跟着余额走，而不是跟着一个当初填下的数字。见[尺寸计算](#尺寸计算)。
- **意外成交。** 成交不是目标。先问场地"现在平掉实际要付多少"，由这个答案决定立刻穿价还是等；仓位平掉之前不再挂任何新的边缘单。见[成交之后](#成交之后)。
- **基线。** 激活时快照账户在该市场已有的仓位和挂单，之后绝不碰它们。有条件就用独立子账户跑。

稳态下每侧最多一张单：**`both` 模式 2 张，`long` / `short` 模式 1 张** —— 基线里的不算。

### 准备

1. 在 pendle 插件里创建 **Boros Agent** 凭证（root 地址 + agent 私钥 + 子账户 id），再基于它建一个 `pendle/rates` 账户。
2. 把保证金充进要做的市场，并给账户的 **gas 余额** 充值（Boros UI → Gas）。充值永远不自动化。
3. 跑 pendle 插件的 **Scan maker incentives** 脚本，挑一个预算在线、池子小的市场。
4. 创建策略实例、选市场，先保持 **Dry run** 开着看日志，确认后再关掉。

### 策略参数

#### 基础

| 参数 | 默认 | 含义 |
|---|---|---|
| `market` | — | 本实例要做的 Boros 市场（从场地目录里选）。一实例一市场。 |
| `dryRun` | `true` | 跟随激励带并记录每一次「本来会发的」撤单/挂单，但不发送。要实盘必须手动关掉。 |
| `marginMode` | `auto` | 订单放在哪个保证金账户。`auto`：市场被标记为仅逐仓时用 isolated，否则 cross。读取、撤单、基线快照都限定在这个账户。 |
| `baselineSnapshot` | `true` | 激活时记录账户在该市场已有的仓位和挂单，之后不碰它们。尽力而为 —— 激活之后手动下的单会被当成意外成交而平掉。关掉 = 市场上的一切都视为策略自己的。 |

#### 规模

| 参数 | 默认 | 含义 |
|---|---|---|
| `sizeMode` | `fixed` | `fixed` = 每次都是同一个 YU 数。`percent` = 按保证金当前能开的量取百分比，每个 tick 重算。 |
| `sizeYu` | `10` | **固定模式。** 每侧挂单量（YU；1 YU = 1 单位抵押币的资金费名义）。每侧奖励份额 = `sizeYu / (池子 + sizeYu)`。 |
| `sizePercent` | `75` | **百分比模式。** 占容量的比例，**每侧各自适用**，不是两边对半分。 |
| `resizeTolerance` | `0.1` | **百分比模式。** 目标量相对已挂量偏离超过这个比例才重挂。 |
| `sides` | `both` | `both` 每侧一张；`long` / `short` 只做一侧。每侧有各自的预算和池子。 |

##### 尺寸计算

百分比模式每 tick、每侧计算：

```
容量 = 该保证金账户的权益 ÷ 场地在挂单利率上对每 YU 要的保证金
可用 = 容量 − 基线已占用的部分
尺寸 = 可用 × sizePercent
```

用的是账户**权益**，不是可用保证金。可用保证金会扣掉策略自己挂着的单，拿它当基数会导致目标量每达成一次就缩水一次 —— 挂了 750 YU，下个 tick 变 187，再下个 608，无限震荡，而每次摆动都是一笔中继交易。权益不会因为我们挂单而变化。

基线要扣掉，因为它不可触碰：它的仓位和挂单占着策略永远收不回的保证金，把这部分算进容量，下出来的单场地会直接拒绝。

`sizePercent` 对**每一侧**生效，不是两边分。利率市场上多空在保证金上基本互相抵消，所以 `75` 就是每边各 75 %。计算用到的每个数都会写进日志；万一哪个场地不再让多空对冲，被拒的会是第二条腿。

`resizeTolerance` 不是可有可无的。容量随每次标记价格波动而变，而每次重挂都是一笔烧 gas 的中继交易 —— 没有这个阈值，策略会整天花钱追噪音。

> **百分比模式需要独立子账户。** 策略靠"挂单量正好等于配置值"来认出自己重启前留下的单，而百分比模式没有这个签名（当时的量取决于当时的余额）。剩下能用的只有"是否落在带内"，这个判据更弱：手工挂在带内的单会被当成自己的撤掉重挂。

#### 走廊

| 参数 | 默认 | 含义 |
|---|---|---|
| `edgeRatio` | `0.95` | 挂单离 mid 的距离，占带宽一半的比例。`0.95` = 刚好在最远边缘内侧（防舍入出带）。 |
| `safeDistanceRatio` | `0.3` | 内线。mid 逼近到不足这个比例的半带宽时，把单重挂回边缘 —— 越靠近盘口成交风险越高。 |
| `requoteIntervalMs` | `30000` | 每侧两次发单的最小间隔，挂单和重挂都受限。合约读数比中继滞后几秒，低于 ~15 s 可能把刚挂的单再挂一次。 |

#### 风控

| 参数 | 默认 | 含义 |
|---|---|---|
| `gasFloorUsd` | `3` | 中继动作从账户链上的 USD gas 余额扣费。低于此值暂停挂单（余额耗尽时场地会静默失败）。 |
| `flattenSlippage` | `0.02` | 平仓 IOC **自身**的限价 —— 它可以越过盘口多远才放弃。这不是"要不要穿价"的判断，那个在成交处理里。 |

#### 成交处理

| 参数 | 默认 | 含义 |
|---|---|---|
| `fillSlippage` | `0.005` | 模拟平仓落点在触价这个范围内就立刻穿价。`0` = 无论多贵都立刻平（旧行为）。 |
| `fillPolicy` | `limit` | 超出预算时怎么办：`limit` / `partial` / `ladder` / `hold`。 |
| `fillTimeoutMs` | `600000` | 持仓超过这么久，无视成本直接穿价。`0` = 不启用。 |
| `fillStopDistance` | `0.15` | mid 向不利方向走了这么多（占开仓利率的比例）就无视成本穿价。`0` = 关。**合成止损**，见下。 |
| `fillSlices` | `4` | 仅阶梯模式。 |
| `fillSliceIntervalMs` | `60000` | 仅阶梯模式。 |

##### 成交之后

做市奖励策略不想要任何仓位，所以成交就是损伤 —— 而平掉它是在两种成本之间选：穿价要付价差和盘口欠缺的深度，而且现在就付；挂着不花钱，但没有截止时间，每一秒利率都可能走得更远。

这正是"立刻 IOC"对最常见那种情况是错的原因：挂在带子边缘的单，**通常是因为市场走过来才成交的**，立刻穿回去等于在一次不利移动上把价差和吃单费实打实亏掉。

所以现在由场地把**整笔平仓单**对着盘口模拟一遍，返回实际能拿到的平均利率 —— 不是价差，价差只是第一个 YU 的价格。这个数和 `fillSlippage` 一比就得出结论：

| 策略 | 超预算时 |
|---|---|
| `limit` | 在触价挂一张 post-only 平仓单等着 |
| `partial` | 先穿掉盘口在预算内能吃下的那部分，剩下的挂着 |
| `ladder` | 每隔一段时间穿一片，中间挂着 |
| `hold` | 保留仓位，但仍然撤掉自己的单 |

基准是**触价，不是开仓价**。开仓价是沉没成本，和"现在穿价贵不贵"无关；拿它做决策会得到那个最要命的反射 —— **越亏越不敢平**。

两个兜底凌驾于所有策略之上，因为"等一个更好的价"是没有终点的计划：`fillTimeoutMs` 和 `fillStopDistance`。**即使场地报不出价它们也会触发** —— 盘口烂到报不出价的时候，恰恰最需要止损。没有兜底触发时，报不出价则是挂着再看，绝不盲目穿价。

**止损是合成的。** Boros 没有条件单（TimeInForce 只有 GTC / IOC / FOK / ALO），所以是策略自己盯着利率、自己打 IOC。**只在引擎运行时有效，反应不快于一个 tick，重启期间完全没有保护。** 比没有强，但不是交易所止损。

这期间策略**不挂任何新的边缘单**：带子边缘正是成交的来源，已经有库存还往那儿加单，就是让一个坏 tick 变成一个真实头寸的方式。`hold` 也会撤单 —— **不平仓不等于把挂单留在那**。

阶梯切的是**发现时**的量而不是剩余量，否则就是芝诺的阶梯：每一步都比上一步小，永远到不了。每一片都是独立的中继交易、独立的 gas —— 切得比省下的价差还细，阶梯就比一次穿价更贵。

### 执行器动作（`pendle-strategy/maker`）

策略的所有动作都走这个执行器；看板的 **Manual fire** 暴露同一组动作。公共字段：

| 字段 | 含义 |
|---|---|
| `marketId` | 场地市场 id（整数，如 `189`）。 |
| `tokenId` | 市场的抵押币 id —— 和 root、子账户一起组成场地寻址用的 `MarketAcc`。 |
| `marginMode` | `cross` 或 `isolated`，订单所在的保证金账户。必须和市场匹配（仅逐仓市场拒绝 `cross`）。 |
| `protectOrderIds` | 绝不能撤的订单 id（基线）。手动触发时留空。 |

| 动作 | 字段 | 作用 |
|---|---|---|
| `requote` | `orders[] {side, sizeYu, apr}`, `cancelSides[]` | **一笔交易：** 先撤掉被触及的每一侧上所有非保护订单，再挂新单。策略每个 tick 用的就是它。 |
| `quote` | `side`, `sizeYu`, `apr` | `requote` 的单侧简写。 |
| `cancel` | `side?`, `orderIds?` | 撤某一侧（或双侧）的非保护订单；`orderIds` 可限定到具体 id。 |
| `flatten` | `baselineSizeYu`, `slippage`, `how`, `maxSizeYu?` | 把仓位推回 `baselineSizeYu`。`how: 'ioc'` 穿价；`how: 'limit'` 在触价挂 post-only 平仓单（幂等 —— 已经挂着的、方向和数量都对的单会保留,不白白丢掉排队位置）。`maxSizeYu` 限制单次量。数量从场地**重新读取**而不是采信调用方：决策到执行之间落下的部分成交，正是平仓冲过头、反向开出一个新仓位的原因。 |
| `simulate*` | 同上 | 只记录将要发出的场地调用，不发送 —— Dry run 用的就是这些。 |

`apr` 是十进制隐含 APR（`0.068` = 6.8 %，允许负数）。`sizeYu` 单位为 YU。
